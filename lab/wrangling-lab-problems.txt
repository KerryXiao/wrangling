When doing this lab with craigslist for cell phones, I ran into several issues. The first of which had to deal with scraping the data properly off the website. For the phone name, this was simple enough as that was present in the card gallery that was present at the website. However, other features and specifications of each individual phone if present was located on another url which was redirected to after the relevant card was clicked on the website. 

Direct HTML scraping returned nothing due to JavaScript rendering and bot protections. RSS access was attempted, however it returned HTTP 403 errors, which indicated server-side request blocking. This showed some limitations of web scraping. A quick look up on the internet showed that Craigslist blocks html and rss requests if it deems them as web scraping. To resolve this a local copy of the website was downloaded into the lab folder in the wrangling fork in order to scrape the data. This was done by just right clicking the website and looking in the View Page Source section. 

There being only 6 cell phones for sale in the Charlottesville region at the current time was also a problem as that meant there was barely any data available for analysis. 

Another issue that was present came up with the two scatterplots. The scatterplots were to plot price vs ram and price vs storage in combination with hues for the phone companies. Unfortunately, those specifications for the phones were lacking in the phone descriptions. Due to this, one scatterplot had no data while the other scatterplot had a single point.
